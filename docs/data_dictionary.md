# Data dictionary

*Phase 1. Describes the tables in `datasets/processed/`, which are what every
later phase reads. Regenerated by `notebooks/02_data_preprocessing.ipynb`; the
machine-readable version is `datasets/processed/feature_lineage.csv`.*

---

## Provenance classes

Every column carries one of four classes. The class is not decoration — the
leakage review in the training phase keys on it directly.

| class | definition | may a model predicting the reference target use it? |
|---|---|---|
| `raw` | straight from a source file: renamed, unit-checked, range-guarded | yes |
| `derived` | computed from raw inputs by a documented transformation that never involves the target | yes |
| `reference` | an agronomic constant looked up from a reference table | yes |
| `reference_derived` | computed from the physics baseline, so algebraically related to the target | **no** |

No column in Phase 1 is `reference` or `reference_derived`. ET₀, Kc and the
target are introduced in the next phase. That ordering is deliberate: it makes
every feature below independent of the eventual target *by construction*, which
is a stronger guarantee than auditing for leakage afterwards.

## `daily_weather.parquet` — 2557 rows × 28 columns

One row per calendar day, 2018-01-01 to 2024-12-31, no gaps.

### Raw observations

| column | unit | source column | notes |
|---|---|---|---|
| `datetime` | date | `datetime` | parsed and sorted ascending; unique, contiguous |
| `t2m` | °C | `T2M` | 2 m air temperature, daily mean |
| `t2m_min` | °C | `T2M_MIN` | 2 m air temperature, daily minimum |
| `t2m_max` | °C | `T2M_MAX` | 2 m air temperature, daily maximum |
| `rh2m` | % | `RH2M` | 2 m relative humidity, daily mean |
| `ws2m` | m/s | `WS2M` | 2 m wind speed — **already at the FAO-56 reference height**, so no wind-height correction is applied |
| `prectotcorr` | mm/day | `PRECTOTCORR` | bias-corrected total precipitation |
| `allsky_sfc_sw_dwn` | MJ/m²/day | `ALLSKY_SFC_SW_DWN` | all-sky downward shortwave irradiance; one day imputed |

All eight come from `Climate_Data.csv` and were renamed to snake_case, had
provider sentinels converted to NaN, and had physically impossible values voided.

The source's `DATE`, `MONTH` and `YEAR` helper columns were checked against the
parsed timestamp — all agreed — and then dropped. A redundant copy that can
silently drift out of step is a hazard, so calendar parts are regenerated from
the timestamp alone.

### Calendar position

| column | unit | derivation |
|---|---|---|
| `year` | year | calendar year |
| `month` | 1–12 | calendar month |
| `day_of_year` | 1–366 | ordinal day |
| `doy_sin` | — | `sin(2π · day_of_year / 365.25)` |
| `doy_cos` | — | `cos(2π · day_of_year / 365.25)` |
| `month_sin` | — | `sin(2π · (month − 1) / 12)` |
| `month_cos` | — | `cos(2π · (month − 1) / 12)` |

The sine/cosine pairs exist because a raw ordinal day tells a model that
31 December and 1 January are 364 units apart, which is exactly wrong for a
seasonal signal. A test asserts the two dates are adjacent in the encoding.

### Weather-derived

| column | unit | derivation | notes |
|---|---|---|---|
| `temp_range_c` | °C | `t2m_max − t2m_min` | proxy for cloudiness; also the input to the FAO-56 radiation estimator |
| `temp_midrange_c` | °C | `(t2m_max + t2m_min) / 2` | |
| `is_rain_day` | 0/1 | precipitation > 0 | |
| `days_since_rain` | days | consecutive dry days, capped at 120 | backward-looking only |
| `rain_sum_7d_mm` | mm | trailing 7-day rainfall total | window ends on the current day |
| `rain_sum_30d_mm` | mm | trailing 30-day rainfall total | window ends on the current day |
| `rain_days_7d` | days | rain days in the trailing 7 days | |
| `rain_days_30d` | days | rain days in the trailing 30 days | |
| `temp_mean_7d_c` | °C | trailing 7-day mean temperature | |
| `temp_mean_30d_c` | °C | trailing 30-day mean temperature | |
| `rh_mean_7d_pct` | % | trailing 7-day mean relative humidity | |
| `rh_mean_30d_pct` | % | trailing 30-day mean relative humidity | |

**Every rolling window is strictly backward-looking.** A centred window would let
tomorrow's rainfall influence today's feature, which is a leak in any forecasting
experiment. `test_rolling_features_never_look_forward` proves it: placing a
500 mm spike on the final day of a synthetic series leaves every earlier row's
rolling features bit-identical.

### Quality flag

| column | unit | meaning |
|---|---|---|
| `allsky_sfc_sw_dwn_was_imputed` | 0/1 | true on 2024-12-04, the one day whose radiation was filled by FAO-56 eq. 50 |

Carried so that any downstream result can be recomputed with imputed days
excluded.

## `crop_stage_reference.csv` — 32 rows

Four FAO-56 stages for each of eight crops. Built by `ml/crop_reference.py` from
`Crop_Calender_cleaned.csv` and `Karnataka_Crop_Growth_Stage_Reference_cleaned.csv`,
with the judgement calls externalised to `config/crop_stages.yaml`.

| column | meaning |
|---|---|
| `crop` | slug: `paddy`, `finger_millet`, `maize`, `groundnut`, `cotton`, `wheat`, `cumin`, `chickpea` |
| `display_name` | label as written in the source file |
| `stage` | `initial`, `development`, `mid_season` or `late_season` |
| `stage_order` | 0–3 |
| `start_day`, `end_day` | stage window in days since sowing or transplanting |
| `duration_days` | `end_day − start_day` |
| `kc_anchor` | the crop coefficient anchoring this stage; null for `development`, which is interpolated |
| `alternative_kc` | a competing published value, retained for the sensitivity experiment |
| `kc_basis` | how the value was obtained |
| `source` | which file it came from |

Stage windows are validated on construction: contiguous, ordered, positive
duration, and anchored at initial, mid-season and late-season. A gap or a missing
anchor raises rather than producing a silently wrong curve.

Kc for any day is obtained from `CropCoefficientModel.kc(crop, days)`, which
follows the FAO-56 four-stage shape — flat at Kc_ini, linear ramp to Kc_mid
across development, flat through mid-season, linear ramp to Kc_end across the
late stage.

## `soil_district_samples.parquet` — 875 rows × 6 columns

| column | unit | notes |
|---|---|---|
| `district` | — | 101 districts across Karnataka, Tamil Nadu and Gujarat |
| `district_key` | — | uppercase, punctuation-free join key |
| `nitrogen` | reported units | heavily piled at the 20.0 minimum; see caveat below |
| `phosphorus` | reported units | |
| `potassium` | reported units | |
| `ph` | pH | clustered tightly near 7.0; values outside 3–10 would be voided, none were |

**Caveats.** No sample date and no field identifier, so this is a district
reference lookup, not a per-field soil record. The nitrogen distribution shows a
hard floor at exactly 20.0 with a median of 20.27, which looks like a reporting
floor rather than a measurement distribution; anything using soil nitrogen
carries that caveat. The reported units are not stated in the source and have not
been independently established.

## `district_rainfall_normals.parquet` — 29 rows × 8 columns

| column | unit | notes |
|---|---|---|
| `district`, `district_key` | — | 29 Karnataka districts |
| `normal_annual_rainfall_mm` | mm/year | long-term normal |
| `normal_rainy_days` | days/year | |
| `raingauge_working`, `raingauge_not_working`, `raingauge_total` | count | network density |
| `serial_no` | — | source row number |

A state-aggregate row was removed during cleaning; leaving it in would have
counted the whole state as a thirtieth district.

**These are annual normals, not a daily series.** They cannot join to a daily
weather record and are not a modelling input. They are used as a regional context
lookup only.

## `season_context.parquet` — 3158 rows × 10 columns

Karnataka cropping context, 2004–2019, across 11 locations: area, rainfall,
humidity, soil type, irrigation method, crop, price and season.

Context only. The raw file's `Temperature` column reaches physically impossible
values and was dropped upstream; it stays dropped.

## `preprocessing_metadata.json`

Written on every run. Records the timestamp, the random seed, the rolling-window
configuration, the latitude used for radiation imputation, row counts per table,
the weather date range, the validation summary and every imputation performed.
This is what makes a set of processed tables traceable to the run that produced
them.

## Files deliberately excluded

| file | why |
|---|---|
| `crop_water_data.csv` | `water_requirement_liters` fails all four ground-truth tests. Retained as a documented negative control. See `docs/dataset_analysis.md` §5. |
| `crop_dataset.csv` | no crop, no date, no location, no stated units for the target. Nothing can be established about it. |
| `data_season.csv` → `Temperature` | physically impossible values, unresolved upstream. |
| `Crop_Calender` → `ETo`, `ETc` | the compiler's own worked example, not measurements. Kc, stage duration, rooting depth and water-holding capacity are used; these two columns are not. |

## What is not in here yet

Introduced in the next phase, and listed now so the gap is explicit:

`et0_mm_day`, `ra_mj_m2_day`, `rso_mj_m2_day`, `rn_mj_m2_day`, `es_kpa`,
`ea_kpa`, `vpd_kpa`, `kc`, `etc_mm_day`, `effective_rainfall_mm`,
`net_irrigation_mm`, `gross_irrigation_mm`.

Everything in that list will be classed `reference_derived` and excluded from any
model that predicts the reference-derived target.
